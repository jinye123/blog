# 用 AI 开发的优劣 + 方法论

> 用 AI 写代码不是"打字加速器"，是新的工作方法。不会用的人 5% 提效，会用的人 5 倍提效。

## 一、优势（真实收益）

### 1. 重复劳动消失

CRUD、Form、Table、CSS 调整、TS 类型定义、单测——这些占据日常 50% 时间的事，AI 能完成 90%。

### 2. 跨技术栈学习成本骤降

不熟 Rust？AI 帮你起步；要写 Go 后端？AI 给你模板。**"不会的我也能上"**，技术边界被打开。

### 3. 文档查询效率 10 倍

不再 Google 跳 5 个网页找答案。直接在 IDE 里问"如何用 Vue3 实现虚拟滚动"，秒回 + 可运行代码。

### 4. 边界条件思考更全

写测试时人容易漏掉 null / 空数组 / 超大输入。AI 一般会想到。

### 5. 思路启发

卡住时让 AI 给 3 个方案对比，自己选。**"AI 是头脑风暴的搭子"**。

### 6. 大型重构成为可能

100 个文件的 API 重命名、框架升级，原来一周的活，现在半天。

### 7. 文档与注释自动化

PR 描述、changelog、JSDoc 注释、README——这些以前没时间写的，现在能写好。

## 二、劣势（真实代价）

### 1. 幻觉

AI 会自信地编造不存在的 API、错误的版本号、过时的语法。

```js
// AI 写出来的：
import { useAtomValue } from 'react';   // ❌ react 没有这个 API
// 实际是 jotai 的 API
```

**对策**：永远怀疑，运行验证。

### 2. 上下文有限

大项目跨文件理解不够。改了 A 文件可能没考虑 B 文件依赖。

**对策**：手动喂关键文件、分批改动。

### 3. 缺乏长期记忆

每次会话都要重新解释项目背景。

**对策**：`.cursor/rules` 沉淀规则、团队 Prompt 模板。

### 4. 让人懒于思考

特别是新人，习惯于"问 AI"而不是"理解原理"。

**对策**：核心模块自己写，AI 只做副驾驶；定期回顾架构、复盘原理。

### 5. 安全与合规

把公司代码贴给云端模型 → 数据泄露风险。

**对策**：
- 企业版（数据不训练）
- 本地模型（Ollama / LM Studio）
- 敏感代码脱敏

### 6. 一致性差

同一问题问两次答案不同（temperature）。

**对策**：用 temperature=0 / 模板化 Prompt / 评测集。

### 7. 上下文越长越慢越贵

128K 上下文听起来美，但每次 API 调用 token 数爆炸。

**对策**：精简上下文、缓存、分块。

### 8. 调试 AI 写的代码反而更花时间

如果你不理解 AI 写的代码，bug 出现时 debug 比自己写还慢。

**对策**：**只让 AI 写你能 review 的代码**。

## 三、方法论（7 条让 AI 真正提效）

### 1. 任务拆解

大任务直接丢给 AI → AI 蒙圈 → 输出垃圾。

正确做法：

```
不要：实现一个完整的购物车系统
要：
  Step 1: 设计购物车的数据结构（TS 类型）
  Step 2: 实现添加 / 删除 / 修改数量的纯函数
  Step 3: 实现状态管理 store（Pinia）
  Step 4: 实现购物车 UI 组件
  Step 5: 接入后端 API
  Step 6: 写单测
```

每步 AI 都能干好，最后拼起来。

### 2. 上下文工程

AI 的回答质量 = f(模型, 上下文质量, prompt 质量)。

```
低质量上下文：
"帮我加个登录功能"

高质量上下文：
"@src/api/auth.ts @src/stores/user.ts
我们的项目用 Vue 3 + Pinia + element-plus。
登录接口已存在（参考 @auth.ts:login），返回 { token, user }。
请实现 Login.vue：
- 用 ElForm + 校验（账号必填、密码长度 6+）
- 调 login → 写入 userStore.setToken
- 成功跳转到 router 的 /dashboard
- 失败 ElMessage.error 显示错误"
```

**对应到工具**：
- Cursor：`@file` / `@folder` / `@codebase` / `@docs` / `@web`
- Copilot：用 `# context:` 注释
- 直接对话：把相关代码块贴进去

### 3. Prompt 四件套

```
[角色] 你是熟悉 Vue3 + TS 的资深前端
[任务] 实现一个虚拟滚动表格
[约束]
- Composition API
- 支持定高 / 不定高
- 泛型支持任意行类型
- ESLint 通过
- 加 JSDoc
[输出]
- 一个 .vue 文件
- 暴露 scrollTo / refresh 方法
```

为什么有效？
- 角色：让 AI 用对的"人格"思考
- 任务：明确产出
- 约束：避免常见走偏
- 输出格式：方便后续处理

### 4. Review 是关键

AI 写完不是结束，是开始。

**Review Checklist**：
- 编译能过吗？
- 类型对吗？
- 边界处理了吗（null / 空 / 异常）？
- 业务逻辑对吗？
- 风格符合项目吗？
- 测试覆盖了吗？

不通过的，让 AI 改；改不对的，自己改。

### 5. 用 AI 做"二次确认"

```
关键代码先自己写 → 让 AI review "有什么 bug / 性能问题"
关键架构先自己设 → 让 AI 给"反对意见 / 替代方案"
关键决策先自己定 → 让 AI 给"风险清单"
```

让 AI 做"魔鬼律师"，而不是主审判官。

### 6. 沉淀 Prompt 库

好 Prompt 是宝藏。建议建：

```
prompts/
├── personal/
│   ├── code-review.md
│   ├── test-generation.md
│   └── refactor.md
└── team/
    ├── pr-description.md
    └── changelog.md
```

每个 Prompt 写：
- 适用场景
- 输入示例
- 输出示例
- 效果评估

### 7. 保持原理思维

**用 AI 不是不学原理，反而要更懂原理**。

- AI 写错了你要看得出
- AI 给出 3 个方案你要选对
- AI 解释不通时你要靠原理判断

原理是判断力的源头。

| CRUD 接口对接 | AI 主导 |
| 表单 / 表格 / 列表 | AI 主导 |

| 单元测试 | AI 主导 |

| 异步并发的微妙逻辑 | 自己主导 |

## 五、常见反模式

### 反模式 1：无脑全自动 Agent

整个项目交给 Agent 跑，下班看结果。
**问题**：Agent 跑歪了你不知道，最后 review 起来比自己写还累。
**建议**：长任务分阶段确认。

### 反模式 2：从不 review

AI 写啥就提交啥。
**结果**：技术债爆炸，bug 来了你看不懂自己的代码。
**建议**：哪怕一行都要懂。

### 反模式 3：所有问题都问 AI

"useState 怎么用？" → 问 AI（懒）
"为什么这个组件渲染两次？" → 问 AI（不思考）
**问题**：原理不学，越用越笨。
**建议**：5 分钟想不出再问 AI。

### 反模式 4：粘贴敏感代码

把含 API Key、用户数据的代码贴给 ChatGPT。
**问题**：合规风险。
**建议**：先脱敏，或用企业版。

### 反模式 5：相信 AI 的"事实"

"React 19 有 useFoo Hook 吗？" AI 信誓旦旦说有。
**问题**：可能是幻觉。
**建议**：去官方文档验证。

## 六、量化你的 AI 使用

每周记录：
- 这周写了多少行代码？AI 占比多少？
- 哪些任务 AI 帮你省了多少时间？
- 哪些任务 AI 反而拖慢了你？
- 这周学到的新原理？

**让 AI 提效是个工程问题，需要持续度量优化。**

## 七、未来 6 个月的演进

1. **Agent 越来越强**：能完成更大跨度任务（OpenAI / Anthropic 都在押注）
2. **多模态融合**：截图 + 语音 + 代码混合输入更自然
3. **本地小模型崛起**：隐私敏感场景的福音
4. **IDE 卷出新高度**：Cursor / Windsurf 在重新发明 IDE
5. **MCP 生态爆发**：标准化协议让工具链复用
6. **企业级 AI 工程岗位**：搭 AI 流水线、做 Prompt 治理、做评测的人会被需要

## 八、面试加分

> "我用 AI 提效有自己的方法论：
>
> **第一**，我不让 AI 写我不懂的代码。复杂业务我自己写骨架，AI 填细节。
>
> **第二**，我建了团队 Prompt 库，把 Code Review、PR 描述、单测生成这些常用任务模板化，团队所有人都能用。
>
> **第三**，我每周看一次 AI 使用度量——哪些任务 AI 真省了时间，哪些反而拖慢，持续调整。
>
> 现在我每天写代码时间从 6 小时降到 2 小时，省下的时间做了 3 个工程基建项目。"
