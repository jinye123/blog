# AI 与前端：认知与定位

> 这一章不写代码，写**判断**。在 AI 重塑研发的当下，前端工程师如何不被替代、如何重新定义价值。

## 一、AI 已经在做什么（现状）

### 1. 写代码这件事，AI 介入已经非常深

- **IDE 智能补全**：Cursor / Copilot / Cody / Windsurf / Trae，已经从"补一行"进化到"写一个模块、跑一次任务"
- **设计稿到代码**：v0.dev / Figma to Code / Galileo，把视觉稿直接转成可运行的 React/Vue 代码
- **Code Review**：CodeRabbit / Copilot Review 自动审查 PR，捕获 bug、坏味道、安全问题
- **单元测试**：Codiumate / Cursor 一键生成测试，覆盖边界条件比人想得更全
- **大型重构**：API 迁移、版本升级、技术栈切换，AI 跨文件批量改写 + 人工 review

### 2. 业务里也在用 AI

- 智能客服 / Chatbot
- 文档智能问答（RAG）
- 智能搜索（embedding + 向量库）
- 内容生成（运营文案、商品描述、营销图）
- 数据分析（自然语言 to SQL）
- 多模态：语音输入、图像理解

## 二、前端角色的三次变化

### 第一次：手写 → 库 / 框架

jQuery 时代的 DOM 工程师，到 React / Vue 时代的组件工程师。

### 第二次：单页应用 → 全栈

Node 兴起，前端开始做 BFF、SSR、工程化基建，能力边界从"页面"扩到"端到端"。

### 第三次（当下）：写代码 → 协同 AI + 做架构 + 做工具

新的能力分层：

| 层 | 内容 | AI 占比 |
| --- | --- | --- |
| 重复劳动 | CRUD、表单、布局、CSS 调整 | **90%** AI 完成 |
| 通用逻辑 | 列表、状态管理、接口对接 | **70%** AI 辅助 |
| 业务理解 | 把模糊需求拆解为代码方案 | **20%** AI 辅助，**80%** 人 |
| 架构设计 | 选型、分层、性能预算、扩展性 | **10%** AI 辅助，**90%** 人 |
| 团队协同 | 规范、Code Review、知识沉淀 | 工具上 AI，决策上人 |

**结论**：AI 把"打字"环节压缩了 80%，把"想清楚"环节的价值放大了 5 倍。

## 三、个人观点：AI 不是替代，是分层

### 不替代什么

1. **业务理解**：产品给你三句话需求，要拆成完整方案，AI 拆不清
2. **架构权衡**：技术栈选型、性能预算、扩展性，需要上下文和判断
3. **跨系统协同**：和后端、设计、产品反复磨合，需要软技能
4. **决策与背书**：方案上线出问题，AI 不背锅
5. **用户体验细节**：动效、交互、可访问性的微妙之处
6. **新场景探索**：业内还没人做过的需求

### 替代什么

1. **重复 CRUD**
2. **样板代码**（脚手架、配置文件、boilerplate）
3. **跨技术栈跳转的学习成本**（不熟 Rust 也能起步）
4. **文档查询**（替代 Google + Stack Overflow）
5. **边界条件思考**（写测试、写文档）
6. **大型重构**

## 四、给前端工程师的三条建议

### 1. 拥抱

不要假装 AI 不存在。今天还在手动写 boilerplate 的人，明年会被会用 AI 的人拉开 5 倍效率差距。

### 2. 深入

把 AI 当"高速复印机"，但你要懂原理。AI 写的代码你要能看懂、能改、能优化。深入到：
- 框架原理（Vue 响应式、React Fiber）
- 浏览器原理（事件循环、渲染流水线）
- 工程化原理（构建工具、模块化）
- 操作系统 / 网络底层

**没有原理，就只能照单全收 AI 的代码**，bug 来了束手无策。

### 3. 做 AI 用不了的事

- 业务建模（把混乱需求结构化）
- 系统设计（前后端协议、分层、性能边界）
- 工程基建（脚手架、CI/CD、监控、组件库）
- 团队协同（规范、Review、知识库）
- AI 工程化（用 AI 来提升团队效率）

## 六、为什么这一章很重要

**面试中如果你能讲清楚 AI 与前端的关系**：
- 你不是把 AI 当"魔法"，而是看清边界
- 你不是焦虑被替代，而是主动拥抱
- 你有具体的落地实践和数据
- 你对未来有判断

→ 这就是面试官眼里的"成长性"。技术深度可以补，但**判断力是稀缺品**。
